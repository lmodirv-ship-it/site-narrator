# خطة الترقية — جودة 4K + صوت مدمج + 100+ صفحة + تحميل MP4

## الأهداف
1. إخراج **MP4 حقيقي** (وليس .webm فقط) بجودة تصل إلى **4K (3840×2160)**.
2. **صوت بشري مدمج** داخل ملف الفيديو (ليس Web Speech فقط أثناء المعاينة).
3. دعم **حتى 100+ صفحة** لكل موقع.
4. زر تحميل مباشر بصيغة **MP4**.
5. تحسينات جودة بصرية (دقة أعلى، خط أوضح، حركة مؤشر أنعم، صور بدقة أصلية).

---

## القيود التقنية الواقعية (مهم جداً قراءته)

بيئة تشغيل المشروع هي **Cloudflare Worker** (سحابية)، وفيها:
- لا يوجد `ffmpeg` كأداة نظام → لا يمكن تحويل WebM→MP4 على الخادم مباشرة.
- لا يوجد متصفح حقيقي للتسجيل بالـ Playwright/Puppeteer.
- زمن التنفيذ محدود (~30 ثانية لكل استدعاء).
- لا يمكن تخزين فيديو 100 صفحة بحجم 4K في الذاكرة دفعة واحدة.

لذلك سأبني الحل على **معماريّة هجينة** تحلّ كل مشكلة:

## المعماريّة الجديدة

### 1) توليد المحتوى (Server Function — موجود ومحسّن)
- زيادة حد الصفحات: `quick=10, medium=30, full=120`.
- جلب الصفحات على دفعات (batching) من Firecrawl بـ 8 صفحات متوازية لتجنّب timeout.
- تخزين السكربتات واللقطات في **Lovable Cloud Storage** (bucket: `tutorials`) بدل إرجاعها كاملة، ثم إعادة قائمة روابط فقط → يحلّ مشكلة حجم الاستجابة لـ 100+ صفحة.
- تقسيم توليد السكريبت على عدّة استدعاءات لـ Gemini (كل 10 صفحات معاً) لتجنّب حدود السياق.

### 2) توليد الصوت البشري (Server Function جديدة)
- استخدام **Lovable AI Gateway → `google/gemini-2.5-flash`** لتوليد نص محسّن، ثم:
- للصوت: **Web Speech API لا يُسجَّل داخل الملف**. الحلول المتاحة بدون ElevenLabs:
  - **الخيار أ (موصى به مؤقتاً):** استخدام Google TTS المجاني عبر REST (translate.google.com/translate_tts) لتوليد MP3 لكل مشهد، وتخزينه في Storage. صوت مقبول بالعربية والإنجليزية.
  - **الخيار ب:** الإبقاء على Web Speech فقط للمعاينة (الوضع الحالي).
- سأنفّذ **الخيار أ** ليصبح الصوت مدمجاً فعلاً في الفيديو النهائي.

### 3) بناء الفيديو MP4/4K (Client-Side — ffmpeg.wasm)
هنا التغيير الجوهري:
- إضافة **`@ffmpeg/ffmpeg` (WASM)** يعمل في المتصفح.
- خط الإنتاج:
  1. الكانفس يرسم كل مشهد بدقة **3840×2160** (4K) أو **1920×1080** (1080p) — اختيار المستخدم.
  2. `MediaRecorder` يسجّل WebM/VP9 بـ bitrate عالي (15-40 Mbps).
  3. ملفات الصوت MP3 لكل مشهد تُجمَّع مع `concat` filter.
  4. `ffmpeg.wasm` يدمج: `video.webm + audio_concat.mp3 → output.mp4` (H.264 + AAC).
  5. زر تحميل واحد يعطي **`tutorial.mp4`**.
- شريط تقدّم واضح: تحليل → سكريبت → صوت → تسجيل → تحويل → جاهز.

### 4) تحسينات الجودة البصرية
- لقطات Firecrawl بـ `fullPage: true` وعرض 1920px.
- خطوط أكبر وأوضح في الترجمة (24-32px على 4K).
- ظل ناعم تحت المؤشر وحركة Bezier أنعم.
- شريط متصفح أكثر واقعية (أيقونة قفل HTTPS، عنوان كامل).
- بطاقة "اسم المشهد" في الزاوية مع رقم الصفحة.
- مقدّمة 3 ثوانٍ (Title card) + خاتمة 3 ثوانٍ ("شكراً لمشاهدتكم").

### 5) واجهة التحكم (HTML)
حقول جديدة:
- **الدقة:** 1080p / 1440p / **2160p (4K)**.
- **مستوى الشرح:** سريع (10) / متوسط (30) / كامل (120 صفحة).
- **الصوت:** Google TTS (افتراضي) / Web Speech (معاينة فقط).
- زرّان: «معاينة» و«إنتاج MP4 وتحميل».
- شريط تقدّم بمراحل واضحة + تقدير المدة المتوقّع.

## ملاحظات حدودية (يجب أن يعرفها المستخدم)

1. **زمن الإنتاج لـ 100 صفحة بدقة 4K:** قد يستغرق **15-40 دقيقة** داخل المتصفح (التحويل عبر WASM بطيء). أقترح أن تكون 4K مفعّلة فقط حتى 30 صفحة، وفوق ذلك تلقائياً ينزل إلى 1080p (مع تنبيه للمستخدم).
2. **الذاكرة:** فيديو 4K لـ 100 صفحة قد يتجاوز 2GB في الذاكرة. سأقسّمه إلى **مقاطع (chunks) كل 20 صفحة** ثم أدمجها بـ ffmpeg.wasm.
3. **جودة صوت Google TTS:** جيدة وطبيعية لكن أقلّ بكثير من ElevenLabs. عندما تجهّز ElevenLabs أربطه فوراً (5 دقائق عمل).
4. **Firecrawl credits:** 100 صفحة = ~100 credit لكل فيديو. تأكد من رصيدك.

## ترتيب التنفيذ
1. إنشاء bucket التخزين + رفع الحدود في `tutorial.functions.ts` + Batching.
2. إضافة `tts.functions.ts` لتوليد MP3 بـ Google TTS وتخزينه.
3. تركيب `ffmpeg.wasm` في الواجهة + `VideoExporter` لإنتاج MP4.
4. ترقية `TutorialPlayer` لـ 4K + تشغيل MP3 المدمج.
5. تحديث الواجهة بحقول الدقة وشريط التقدّم.
6. اختبار end-to-end: موقع صغير (5 صفحات) → MP4 1080p → ثم 30 صفحة 4K.
