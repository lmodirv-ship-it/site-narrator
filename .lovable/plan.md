## القرار المعماري

نتوقف عن الاعتماد على تسجيل المتصفح المباشر داخل HTML (canvas + MediaRecorder + File System Access)، لأنه يسبب مشاكل صلاحيات، ومشاركة شاشة، وحفظ غير مضمون. ننقل التسجيل الحقيقي إلى خادم محلي يعتمد على Playwright + FFmpeg، بينما تبقى واجهة الويب مجرد لوحة تحكم.

```text
┌────────────────────┐        ┌─────────────────────────────┐
│  Web UI (HTML/JS)  │ ─────► │  Local Server (Node)        │
│  - إدخال الرابط    │  HTTP  │  - Playwright يفتح الموقع   │
│  - مجلد العمل      │        │  - يلتقط الفيديو 30s/جزء    │
│  - زر Generate     │        │  - FFmpeg يدمج final.mp4    │
│  - لوحة الحالة     │ ◄───── │  - يكتب video-info.txt      │
└────────────────────┘  SSE   └─────────────────────────────┘
```

## مرحلة «تنظيف وتثبيت» (هذه المرحلة فقط — بدون ميزات جديدة)

### 1. تعطيل التسجيل داخل المتصفح كمسار أساسي
- في `src/components/RecorderStudio.tsx`:
  - تعطيل التشغيل التلقائي نهائياً (إزالة `useEffect` الذي يستدعي `startPlayback` عند توفر `dirHandle`).
  - وضع وسم واضح فوق الاستوديو: «وضع المعاينة داخل المتصفح — لإنتاج MP4 حقيقي استخدم الخادم المحلي».
  - الإبقاء على الكود الحالي كخيار ثانوي قابل للطي، بدون حذف أي شيء.

### 2. اشتراط مجلد العمل قبل أي توليد
- زر Generate في `src/routes/index.tsx` يصبح معطّلاً حتى يتم اختيار «مجلد العمل».
- مجلد العمل يُحفَظ في `usePersistentState` ويُمرَّر إلى الخادم المحلي مع كل طلب.
- رسائل الواجهة موحَّدة: قبل اختيار المجلد تظهر «اختر مجلد العمل أولاً»، وبعد الاختيار «جاهز: <اسم المجلد>».

### 3. إضافة خادم محلي مستقل (مجلد جديد `local-server/`)
- مشروع Node صغير منفصل عن TanStack:
  - `local-server/package.json` — التبعيات: `playwright`, `fluent-ffmpeg` أو استدعاء `ffmpeg` مباشرة، `express`.
  - `local-server/src/index.ts` — يستقبل `POST /jobs` بـ `{ url, workDir, pagesPlan, secondsPerSegment: 30 }`.
  - `local-server/src/recorder.ts` — يفتح Playwright، يسجّل الصفحة، ويقطع كل 30 ثانية إلى `segment-XXX.mp4`.
  - `local-server/src/merge.ts` — يدمج الأجزاء عبر FFmpeg `concat` إلى `final.mp4`.
  - `local-server/src/info.ts` — يكتب `video-info.txt` (الرابط، التاريخ، عدد الأجزاء، المدة، الإعدادات).
  - `GET /jobs/:id/events` (SSE) — لإرسال التقدم والمراحل إلى الواجهة.
- يعمل على `http://localhost:5174` ويُشغَّل بأمر `cd local-server && npm start` (تعليمات في README).

### 4. ربط الواجهة بالخادم المحلي
- في `src/lib/tutorial.functions.ts` نضيف عميل HTTP خفيف يتصل بـ `http://localhost:5174` ويفتح SSE لعرض التقدم.
- لوحة الحالة في الواجهة تعرض:
  - الجزء الحالي (مثلاً `segment-003.mp4`)
  - المدة المنقضية
  - عدد الأجزاء المكتملة
  - حالة الدمج النهائي
  - حالة كتابة `video-info.txt`
- إذا تعذّر الاتصال بالخادم المحلي، تظهر رسالة واضحة: «شغّل الخادم المحلي أولاً: `npm start` داخل `local-server/`».

### 5. توحيد النصوص وإزالة الوعود غير الممكنة من واجهة HTML
- إزالة أي نص يوحي بأن المتصفح وحده ينتج MP4 مضموناً.
- استبدال نص «بدء / إعادة إنشاء الفيديو» داخل الاستوديو بـ «معاينة داخل المتصفح فقط».
- زر «إنتاج MP4 حقيقي» الوحيد يستدعي الخادم المحلي.

## ما يُسلَّم في نهاية هذه المرحلة

- مسار أساسي واحد واضح: مجلد العمل → Generate → الخادم المحلي → أجزاء كل 30ث → `final.mp4` + `video-info.txt`.
- المسار القديم (تسجيل داخل المتصفح) يبقى موجوداً ومعزولاً تحت تسمية «معاينة».
- لا حذف لأي كود قائم بدون طلب صريح.

## ما لا يتم في هذه المرحلة

- لا ميزات تحرير جديدة، لا مؤثرات إضافية، لا تغيير في TTS أو EQ.
- لا تغيير في schema قاعدة البيانات.
- لا نشر أو CI — التشغيل محلي فقط.

## التحقق بعد التنفيذ

- `cd local-server && npm install && npm start` يرفع الخادم على المنفذ 5174.
- الضغط على Generate بدون مجلد عمل: زر معطّل.
- بعد اختيار مجلد وضغط Generate: تظهر أجزاء `segment-001.mp4`, `segment-002.mp4`… داخل المجلد كل 30 ثانية.
- في النهاية يظهر `final.mp4` و `video-info.txt` في نفس المجلد.
- إيقاف الخادم أثناء العمل يعرض رسالة خطأ واضحة في الواجهة بدلاً من تجمّد.
